# Two Real Approaches — Choose One First

| Approach | What It Means | Time | Best For |
|---|---|---|---|
| **A. Capacitor Wrapper** | Wrap your existing Angular app in a native shell | 1–2 weeks | Fast launch, reuse everything you built |
| **B. React Native Rebuild** | Build a separate native app from scratch (your original plan) | 2–3 months | Best native performance, was your original tech stack |

**My honest recommendation: Start with Capacitor.** You already have a fully working Angular app with auth, bookings, payments, chat — all of it. Capacitor wraps it into a real Android app in days, not months, and gets you on the Play Store while you validate demand. If it takes off, you migrate to React Native later with real user data justifying the investment.

I'll walk you through **Capacitor** completely since that's the realistic path given where you are.

# Part 3 — Handle Mobile-Specific Concerns

Your app currently uses `localStorage` for JWT tokens and WebSocket connections — both work fine in Capacitor's WebView, but a few things need attention.

### Step 1 — Install Capacitor Plugins You'll Actually Need

```cmd
npm install @capacitor/status-bar @capacitor/splash-screen @capacitor/app @capacitor/network @capacitor/push-notifications
```

### Step 2 — Handle Back Button (Android hardware back button)

Open `src/app/app.component.ts`, add:

```typescript
import { Component, OnInit } from '@angular/core';
import { RouterOutlet, Router } from '@angular/router';
import { App } from '@capacitor/app';
import { Capacitor } from '@capacitor/core';
import { AuthService } from './core/services/auth.service';
import { WebsocketService } from './core/services/websocket.service';

@Component({
  selector: 'app-root',
  standalone: true,
  imports: [RouterOutlet],
  templateUrl: './app.component.html',
  styleUrl: './app.component.scss'
})
export class AppComponent implements OnInit {
  title = 'evenzoo-frontend';

  constructor(
    private authService: AuthService,
    private ws: WebsocketService,
    private router: Router
  ) {}

  ngOnInit() {
    if (this.authService.isLoggedIn()) {
      this.ws.connect();
    }

    if (Capacitor.isNativePlatform()) {
      this.setupBackButton();
    }
  }

  setupBackButton() {
    App.addListener('backButton', ({ canGoBack }) => {
      if (!canGoBack || this.router.url === '/customer/home' || this.router.url === '/login') {
        App.exitApp();
      } else {
        window.history.back();
      }
    });
  }
}
```

### Step 3 — Handle Status Bar Styling

Update `src/app/app.component.ts` to also set status bar color on launch:

```typescript
import { StatusBar, Style } from '@capacitor/status-bar';

// Add inside ngOnInit, within the Capacitor.isNativePlatform() check:
if (Capacitor.isNativePlatform()) {
  this.setupBackButton();
  StatusBar.setBackgroundColor({ color: '#1a1a2e' });
  StatusBar.setStyle({ style: Style.Dark });
}
```

### Step 4 — Fix API URL for Mobile (Critical)

Your app currently points to `http://127.0.0.1:8000` in dev and your Railway URL in production. On a real phone, `127.0.0.1` means the phone itself, not your computer — this will break during testing unless handled correctly.

Open `src/environments/environment.ts` (used only for local dev):

```typescript
export const environment = {
  production: false,
  apiUrl: 'http://127.0.0.1:8000/api'  // fine for browser testing, NOT for real device testing
};
```

For testing on a real Android device during development, you need your computer's local network IP instead. Create a new file `src/environments/environment.mobile-dev.ts`:

```typescript
export const environment = {
  production: false,
  apiUrl: 'http://192.168.1.X:8000/api'  // replace X with your actual computer's LAN IP
};
```

Find your computer's IP:
```cmd
ipconfig
```
Look for "IPv4 Address" under your active network adapter.

Your **production** build (what you'll actually submit to Play Store) should always point to your live Railway URL — confirm `environment.prod.ts` has that already set from Week 18.

### Step 5 — Update WebSocket Service for Capacitor Compatibility

Your `websocket.service.ts` already builds the URL dynamically from `environment.apiUrl`, so no changes needed there — it will correctly use `wss://` against your Railway backend once built for production.

# Part 9 — Handle Payments Correctly on Mobile

Razorpay Checkout.js (the script tag approach from Week 15) works differently inside a native WebView. You have two options:

**Option A — Keep it simple (works, slightly less polished):** Razorpay's web checkout still opens correctly inside Capacitor's WebView since it's just JavaScript running in a browser context. Test this first — it likely works without changes.

**Option B — Use Razorpay's native Capacitor plugin (more polished):**

```cmd
npm install razorpay-capacitor
npx cap sync android
```

This gives a native payment sheet instead of a web popup. If Option A works fine in your testing, skip this — don't add complexity you don't need yet.

# Part 10 — Prepare for Play Store Submission

### Step 1 — Create a Google Play Developer Account

Go to [play.google.com/console/signup](https://play.google.com/console/signup)

- Pay the one-time **$25 USD registration fee**
- Fill in your developer details (can be individual or organization)
- This takes a few hours to a couple days for Google to verify

### Step 2 — Generate a Signed Release Build

Your app needs to be **signed** with a cryptographic key before Play Store accepts it.

In Android Studio: **Build → Generate Signed Bundle / APK**

Choose **Android App Bundle** (Google's required format, not APK, for new apps).

Click **Create new...** to generate a keystore:
```
Key store path: Choose a safe location, e.g. C:\Evenzoo\evenzoo-release-key.jks
Password: [create a strong password — SAVE THIS SOMEWHERE SAFE]
Alias: evenzoo
Alias password: [another strong password]
Validity: 25 years
Certificate info: Fill in your name/organization details
```

**Critical: back up this keystore file and both passwords somewhere safe outside your computer (cloud storage, password manager).** If you lose it, you can never update your app again — you'd have to publish as a brand new app from zero.

### Step 3 — Build the Release Bundle

After creating/selecting your keystore, choose:
```
Build Variant: release
```

Click Finish. Android Studio produces a `.aab` file (Android App Bundle) at:
```
android/app/release/app-release.aab
```

You need these before you can submit:

| Asset | Requirement |
|---|---|
| App icon | 512×512px PNG |

| Short description | Max 80 characters |
| Full description | Max 4000 characters |
| Privacy Policy URL | **Mandatory** — must be a real, publicly accessible URL |

### Quick Privacy Policy Solution

Since this is genuinely required (Google rejects apps without it), create a simple one:

```cmd
ng generate component core/components/privacy-policy --standalone
```

Write basic content covering: what data you collect (name, email, phone, booking history), how it's used, that payments go through Razorpay, contact email for privacy concerns. Host this page at a URL like `https://evenzoo.vercel.app/privacy-policy` — since your frontend is already on Vercel, this is just another route.

### Step 1 — Create Your App Entry

In [Play Console](https://play.google.com/console), click **Create app**:
```
App name: Evenzoo
Default language: English (India)
App or game: App
```

### Step 2 — Complete the Store Listing

Navigate through: **Store presence → Main store listing**
- Upload your icon, feature graphic, screenshots
- Fill short and full description
- Add your Privacy Policy URL

### Step 3 — Complete App Content Declarations

Google requires you to answer questionnaires about:
- **Content rating** — answer honestly (Evenzoo is general audience, no violence/adult content)
- **Target audience** — likely 18+ given payment/business functionality
- **Data safety** — declare what data you collect (name, email, phone, location, payment info) and confirm it's encrypted in transit (yes, since you use HTTPS/Railway/Vercel)
- **Ads declaration** — declare "No" since Evenzoo doesn't show ads

### Step 4 — Upload Your App Bundle

Navigate to **Production → Create new release**

Upload your `app-release.aab` file from Part 10.

Add release notes:
```
Initial release of Evenzoo — find, book and pay event vendors online.
```

### Step 5 — Review and Submit

Click through the final review screen, confirm everything, and **Submit for review**.

# Part 13 — What Happens After Submission

Google's review typically takes **a few hours to 7 days** for new developer accounts (first app review is usually slower and more scrutinized than subsequent updates).

You'll get an email when it's either:
- **Approved** → live on Play Store within a few hours
- **Rejected** → with specific reasons (common first-time issues: missing privacy policy, incomplete data safety form, crashes on review devices)

# One Important Reality Check

Before you spend two weeks on this: **your web app already works on mobile browsers.** Angular Material is responsive, and anyone can open `evenzoo.vercel.app` on their phone right now and use the full product — book vendors, pay, chat, everything.

A Play Store app matters mainly for **discoverability** (people searching "event vendor app" in Play Store) and **trust perception** (a real app feels more legitimate than a website to many Indian users). But it's not blocking anyone from using Evenzoo today.

Given where you are — still validating with your first vendors — I'd suggest: **get 5-10 vendors actually using the web app successfully first.** If they ask "is there an app?" or if you notice mobile web usage is high but conversion is low, that's your signal this Play Store investment will pay off. If nobody's asking, this two weeks might be better spent on Tier 1 items from our gap analysis (rate limiting, email notifications, legal pages) that protect the product you already have.

Your call — but wanted to name that trade-off honestly before you commit two weeks to this.
